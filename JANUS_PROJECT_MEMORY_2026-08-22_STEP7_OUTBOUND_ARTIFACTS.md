# JANUS checkpoint — Step 7 outbound working artifacts

Date: 2026-08-22

Step 7 of the post-Step-7 server roadmap is implemented.

## Purpose
JANUS can now externalize durable working products from its persisted project/research state instead of only describing them in Chat. These are account-bound files and are explicitly not hidden chain-of-thought.

## Implementation
- `attachment_api.store_generated_file()` stores trusted server-generated bytes through the existing JANUS file subsystem.
- Generated files receive normal account binding, hashing, persistent storage, text extraction and document-grounding indexing.
- `outbound_artifacts.py` exposes authenticated `/artifacts` create/list/info routes.
- Initial artifact kinds:
  - `continuity_report`: current + historical continuity ledger export.
  - `project_snapshot`: one project/question/task/etc. plus append-only lifecycle history.
  - `research_digest`: completed curiosity/web research plus recorded sources and cross-research synthesis records.
  - `working_note`: explicit durable note supplied for export.
- Artifact metadata records provenance, optional continuity item, owner account/profile, linked JANUS file id and creation time.
- Existing `/files/{file_id}/download` remains the authenticated download mechanism.
- Baseline artifact creation is deterministic and uses zero model/API calls.

## Safety / epistemic boundaries
- Artifacts contain externalizable persisted records only, not private chain-of-thought.
- Account isolation is preserved by the existing authenticated file store and artifact metadata scope.
- Historical, provisional, unresolved and contradicted material remains labelled by persisted lifecycle state rather than rewritten as current truth.
- Research digests preserve retrieval source records where available.

## Regression coverage
`tests/test_outbound_artifacts.py` verifies:
1. account-bound generated file storage and document indexing;
2. project lifecycle-history export;
3. research digest + source export;
4. cross-account isolation.

CI coverage is in `.github/workflows/test-curiosity.yml`.
